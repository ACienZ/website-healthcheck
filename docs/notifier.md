# Gmail 汇总告警模块

实现位于 `src/website_healthcheck/notifier/notifier.py`，使用标准库 `smtplib`、`ssl` 和 `email`，没有新增依赖。测试位于 `tests/test_notifier.py`。

## 职责与调用顺序

`send_alert(report, mail_settings) -> None` 将一个 `Report` 快照生成一封纯文本邮件并发送，失败抛出可展示的 `MailError`。它不查询数据库、不计算邮件间隔，也不修改事件通知状态。

完整入口已在步骤 5 接入，顺序如下（详见 [命令与调度说明](scheduling.md)）：

1. 当前检查完成后，调用 `Storage.pending_report(now, mail.interval_minutes)`。
2. 返回 `None` 说明无事件、间隔未到或仍有运行，不调用发信；首次事件可以立即发送。
3. 有报告则记录尝试开始时间，调用 `send_alert`。
4. 成功后调用 `Storage.record_delivery(report, "success", attempted_at)`；捕获 `MailError` 后记录 `"failed"`。

成功才标记本批事件；失败保留，成功和失败尝试都会推进最小邮件间隔。`send_alert` 不做内部循环重试，不自行等待下一个邮件周期。直接传入空事件报告也不会连接 SMTP。

## 邮件内容

邮件头包含主题、发件人、全部收件人和报告生成日期。正文统一显示 UTC 时间，包含：

- 统计区间、事件 ID 及记录/发现时间。
- 页面最终失败对应的检查 ID、运行 ID、目标及全部尝试；每次显示状态码、请求耗时、关键词结果、失败原因和已取得的最终 URL。
- 实际重试次数为尝试总数减一，不是配置中的允许最大重试次数。
- 漏跑区间包含首尾计划时段，明确不补跑；中断显示运行 ID，说明发现时间不代表实际中断时间。
- 历史故障与各目标最新已完成状态分开展示；故障后已恢复仍保留历史。没有已完成检查时明确说明未知，不能写成健康。

网络错误时，未取得的状态码和未判断的关键词会明确展示，不用 `0` 或 `False` 代替未知。不会附带网页正文、原始网络异常、SMTP 密码或完整配置对象。

## SMTP 与失败边界

采用配置中的主机、端口、超时、账号、发件人及收件人；默认 Gmail `SMTP_SSL` / 465。使用 `ssl.create_default_context()` 校验证书与主机名。仅登录时读取 `SecretStr` 明文，不输出 SMTP 调试交互；连接、认证、发送和关闭错误转换为固定的脱敏消息，隐藏默认异常链。

SMTP 全部拒收会抛异常；部分拒收可能返回字典，模块也将其视为失败。部分地址已被接受时仍保留整批事件，重试可能导致已接受者收到重复邮件。SMTP 接收并不保证最终进入收件箱。

SMTP 接收后、数据库提交前崩溃，或邮件已被接受但关闭连接时出错，下一轮也可能重复发送。这与存储模块约定一致，不承诺严格一次投递。模块不绕过 Gmail 的应用专用密码要求，也不验证真实账号可用性。
